## 1. 用途、事实边界与已核对现状

本文件是后续扩展 SignRiver DLC Hub“报错指南 / 常见问题教程 / 一键排错”时的**内容决策台账**。它不把旧指南的经验性结论直接视为事实，也不授权自动改系统、改游戏文件、下载 DLL、运行未知工具或改变安全软件设置。

已核对的现状：

- 当前客户端已具备本地解决方案页、云端指南目录、问题记录详情与“查看对应解决方案”入口；云端 `GuideCatalogService` 目前只支持 `all`、`windows`、`steamos`、`macos` 平台过滤，尚不支持按游戏卡带、启动器或游戏版本过滤。
- 当前“一键排错”只读检查网络目录状态、已选游戏目录及磁盘空间、适用补丁审计状态和近期问题记录；异常结果以解决方案 ID 跳转，不直接修复。
- 当前稳定问题码仅能可靠覆盖本程序已记录的网络、补丁、文件系统与更新类异常；不能把游戏自身闪退、Steam 客户端、显卡驱动或第三方启动器的症状伪装成已有 `ProblemCode`。
- 旧 Word 文档以《群星》、Paradox Launcher、特定 DLC 注入方案和第三方工具为背景，不能将其原始原因或修复操作默认推广到其他游戏。

## 2. 筛选原则与安全边界

### 2.1 主结论定义

每个来源主题只分配一个**主结论**；一个主题里的不同可能原因可在第 4 节拆成多个候选项。

| 主结论 | 准入条件 | 典型程序落点 |
| --- | --- | --- |
| 通用指南候选 | 多款 Steam 游戏或本程序通用；步骤低风险、可解释、可复核 | “解决方案”搜索目录 |
| 程序/DLC 工作流候选 | 与 Hub 的目录、下载、补丁、资源发布、文件完整性或问题记录直接相关 | DLC/补丁解决方案、问题记录联动 |
| 游戏或启动器特化候选 | 依赖游戏、引擎、启动器、版本、Mod、存档或联机规则 | 未来按游戏卡带显示的指南 |
| 一键排错候选 | 可只读检查，结果可判定，异常后有确定的指南 ID | “简单错误检测”结果行 |
| 排除 / 待验证 | 非官方链路、第三方工具、时效性/经验性断言、高风险操作或证据不足 | 不上线；保留验证任务或转人工/官方支持 |

### 2.2 已锁定的禁止与约束

- 仅处理官方 Steam、已支持游戏、操作系统环境和 SignRiver DLC Hub 本身的官方链路；学习版、联机加速器、SteamCMD/创意工坊下载流程均不进入未来程序指南候选。
- 不自动关闭 Defender、受控文件夹访问或任何安全防护；不自动添加白名单、恢复隔离文件、修改注册表、长期提升管理员权限、下载/复制 DLL 到系统目录，或运行来源不明脚本。
- “安全软件疑似干扰”只能描述为启发式分类：让用户在安全软件历史中核对来源与哈希，并跳转到可解释的指南；不得武断归因或代替用户作安全决策。
- 历史版本 Bug、固定年份/事件触发的崩溃、特定存档、Mod 冲突、启动器私有数据库错误均须在有当前版本复现和适用条件前保持“特化/待验证”。
- 所有未来可执行工具继续遵循现有边界：适用平台过滤、HTTPS、非空下载、临时文件原子替换、用户明确确认；本目录不新增工具发布要求。

### 2.3 一键排错准入门槛

一项检查必须同时满足以下条件才可列入“一键排错”：

1. 只读取本机状态，不修改游戏文件、系统设置、网络设置或安全策略；
2. 对所有平台通用，或能由卡带元数据准确限定当前游戏/平台；
3. 输出可明确判定为正常、异常或无法判断；
4. 异常（及“无法判断”）均有固定的详情指南 ID 可跳转；
5. 检查失败本身不能中断客户端，且不泄露账号、路径中的敏感信息或原始日志。

| 触发条件 | 可映射的主指南 | 规则 |
| --- | --- | --- |
| `NET_TLS` | `network-basics` | 内容解释 TLS、系统时间、网络与重试；不指导代理或证书绕过 |
| `NET_TIMEOUT`、`NET_DNS`、`NET_HTTP`、`NET_CONNECTION` | `network-basics` | 保留下载源、网络与重试建议 |

## 8. 后续验证清单与完成标准

### 8.1 验证队列

1. 对每一条 `P0` 候选，验证其指南文案不承诺无法观测的根因，并能在现有 UI 中落到唯一详情页。
2. 对 `game-directory-missing`、`patch-state`、`patch-assets-missing`，用至少一个 Windows、SteamOS、macOS 卡带/资源状态组合验证平台过滤与异常文案。
3. 对所有游戏/启动器特化条目，收集游戏 ID、平台、版本、日志/错误码和最小复现步骤后，才将 `verification_status` 提升为 `verified`。
4. 对 Windows 显示、Documents、运行库和安全软件条目，只验证只读检测的准确性；不以测试为由自动修改系统。
5. 每个未来可执行工具都需独立完成来源、适用平台、用户确认、失败回退和不影响一键排错的验证。

### 8.2 目录验收标准

- 本文件的来源盘点覆盖源 DOCX 全部一级、二级主题，且每行有段落定位、旧方案摘要、唯一主结论和程序落点。
- 每个拟上线候选包含适用范围、平台、症状、低风险步骤、风险、落点和验证状态。
- 每个一键排错候选都有只读方法、正常/异常/无法判断文案和固定的详情跳转目标。
- 未把学习版、联机加速器、SteamCMD、自动关闭防护、自动系统设置变更、未知脚本或散装 DLL 下载列为可上线方案。
- 实施阶段如新增 schema、问题码、卡带字段或 UI 跳转，必须单独编写实现计划、补测试并遵守现有多端与云端发布约束。
