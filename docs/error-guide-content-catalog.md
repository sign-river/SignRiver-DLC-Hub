# 指南内容与交互规范

本文档只定义随客户端发布的本地指南与常用工具项规则。指南索引、正文、图片和 `tools_index.json` 均来自 `config/guides/`；云端仅承载工具实际下载文件，不承载指南或工具项定义。

## 1. 适用范围

- 内置指南和云端拓展指南必须遵循同一正文结构、内容边界和交互规则。
- `guide_id` 是指南的稳定主键，用于索引、搜索、问题跳转、按钮跳转和云端更新；创建后不得随意改名。
- 指南索引至少声明 `guide_id`、标题、摘要、`summary_type`、正文资源名和 `platforms`。
- `summary_type` 必须固定为 `"problem_detail"`；发布器会拒绝缺失或其他取值的指南索引。
- 标题下的 `summary` 是问题细节：只描述用户可观察到的异常现象、缺失内容或报错结果，例如“未检测到游戏安装目录”或“补丁文件下载后消失”。不得概括文章内容，也不得写“检查”“重试”“重新下载”“打开工具”等处理步骤。
- `platforms` 只用于控制显示范围，不能代替真实资源可用性或问题判断。
- 指南正文只承接程序能够观察、验证或明确提示的现象；游戏专属、启动器专属或未经验证的内容必须限制适用范围，不得包装成通用结论。

## 2. 正文固定格式

所有指南按以下顺序组织正文：

1. 标题摘要：使用 `summary_type: "problem_detail"`，用于描述问题细节，不重复正文步骤；
2. `常见原因`：第一个正文大标题，说明可能触发该问题的情况；没有可靠原因时，使用谨慎的可能性表述；
3. `建议操作`：第二个正文大标题，给出低风险、可执行且有明确顺序的处理步骤；
4. 可选的图片或其他补充内容：放在对应操作说明之后；
5. `仍无法解决时`：最后一个正文大标题，说明应保留哪些问题记录或诊断信息并联系开发者；
6. 联系入口：使用可点击的开发者联系链接。

`常见原因`可以只有一段简短说明，但 `建议操作` 和 `仍无法解决时` 是固定段落。不得把同一段操作重复放在摘要、原因和建议操作中。

## 3. 正文块与链接

正文使用受控块表达内容：

- `heading`：正文小标题；固定格式中的标题文字必须保持一致；
- `text`：普通说明或操作步骤；避免大段不可执行的背景介绍；
- `image`：指南配图，使用 `asset_name` 引用随指南发布的附件；
- `link`：开发者联系或其他允许的 HTTPS 外链；
- `button`：客户端内部导航，只能使用已登记的受控目标；需要进入工具管理时使用 `tool:<tool_id>`，工具下载、启动和删除均在工具详情页完成。

`summary` 与 `text` 正文块在客户端统一使用只读文本框渲染：按字符自动换行、根据显示行数调整高度，不依赖固定像素 `wraplength`；外层指南滚动容器负责滚动。工具详情中的说明正文沿用同一渲染约定。

外链必须使用 HTTPS，并在界面中以可点击链接显示。内部按钮不得声明命令、脚本、任意 URL 或任意回调；工具启动必须通过工具目录和既有动作白名单完成。

## 4. 图片资源规则

- 图片文件放在指南发布目录的 `assets/` 下，使用平铺文件名，不得包含路径穿越、绝对路径或任意外部地址。
- 指南和工具项使用 `asset_name`，发布器必须校验引用存在、文件名合法，并将定义同步到 `config/guides/`。
- 客户端按指南 ID 将图片缓存到对应目录；云端资源刷新或下线时不得破坏已有内置指南和其他指南缓存。
- 预览图受正文实际可用宽度限制，按页面尺寸动态计算；不得使用固定像素宽度作为跨窗口布局规则。
- 点击预览后在独立图片窗口中查看，支持滚轮自由缩放；关闭查看窗口后返回原指南页面。

## 5. 指南与工具的互相跳转

指南可以在正文中按需声明跳转到受控工具详情、DLC 主页或另一篇指南；工具详情也可以声明跳转到指南。指南详情顶部不再放置固定的工具管理按钮，所有工具下载、启动和删除均由工具详情页负责。所有跳转必须遵守以下规则：

- 跳转目标必须存在、通过平台过滤，并由客户端白名单解析；无效目标只记录可恢复错误，不得阻断指南显示。
- 第一次发生跳转时记录导航初始入口；后续页面只能保存当前返回上下文，不能覆盖初始入口。
- 从指南进入工具或工具详情后，返回按钮回到发起跳转的页面；发起页面的返回按钮仍回到最初入口。
- 从工具进入指南时使用同样规则；不得让两个详情页互相替换返回目标形成无限循环。
- 用户通过列表、搜索或首页直接打开的页面，其右上角返回按钮保持原有页面层级，不得被后续内部跳转改写。

## 6. 云端拓展指南

- 指南索引、正文 JSON 和普通图片附件不上传云端，随客户端小版本发布。
- 工具包可上传到 `tools` Release，但不得上传或依赖云端 `tools_index.json`；新增或修改工具项必须随客户端版本更新。
- 云端指南只能追加新条目或更新允许更新的拓展条目；不得覆盖客户端内置的固定指南、工具或安全边界。
- 云端正文必须使用与内置指南相同的块类型、图片字段、链接规则和按钮白名单；客户端不得为云端内容提供额外权限。
- 指南发布前必须校验：索引与正文一一对应、`guide_id` 不重复、图片引用存在、平台字段合法、按钮目标可解析、外链符合 HTTPS 规则。
- 云端刷新失败、资源缺失或内容格式错误时，继续显示可用的内置内容或旧缓存，并记录可诊断信息。

## 7. 内容安全与表达边界

- 建议操作以重试、重新扫描、切换受支持设置、查看状态和收集诊断信息为主；不得默认修改游戏文件、系统设置、防护策略或网络配置。
- 不提供散装 DLL、来源不明的下载工具、绕过授权、关闭防护、自动加入白名单或要求长期管理员运行等高风险步骤。
- 涉及安全软件、平台限制、云端资源或第三方服务时，只描述可观察现象和用户可自行确认的低风险步骤，不把可能性写成确定根因。
- 每篇指南最后必须提供开发者联系入口，并提示附上问题记录、错误详情或诊断信息。

## 8. 修改与验收要求

每次新增或调整指南格式、块类型、图片、链接、跳转或云端发布行为时，必须同时检查内置和云端两套路径，并在本规范中更新对应规则。

提交前至少完成：

1. JSON 结构和资源引用校验；
2. 正文块顺序、固定标题和链接/按钮目标检查；
3. 图片缓存、动态宽度预览和缩放行为的定向测试（涉及图片时）；
4. 指南与工具返回路径的定向测试（涉及跳转时）；
5. 平台过滤、云端刷新失败回退和内置内容保护检查（涉及发布或平台字段时）；
6. `git diff --check`。

未执行的验证必须在交接记录中明确标注，不得用历史测试结果代替本次改动的验证。
