# 发布器重构真实验收清单

> 状态：待人工执行
> 更新日期：2026-08-17
> 用途：阶段 6 旧入口下线前的真实双源、故障恢复和 UI 对等验收

## 1. 记录规则

- 使用专门的测试版本或测试范围，不覆盖当前正式清单引用的产物。
- GitLink、GitHub 令牌只在发布器本地输入，不写入本文、截图文件名、日志或 Git。
- 每个步骤记录“通过 / 失败 / 未执行”、时间、批次 ID、脱敏证据位置和问题摘要。
- 失败后先导出批次诊断与脱敏审计，不直接重复点击发布。
- 未执行项必须保持“未执行”，不得由自动化测试结果代替真实远端或人工 GUI 结论。

## 2. 前置材料

- [ ] Windows x64 原生候选包，版本、大小和 SHA-256 已记录。
- [ ] SteamOS x64 原生候选包，版本、大小和 SHA-256 已记录。
- [ ] macOS Intel x64 原生候选包，版本、大小和 SHA-256 已记录。
- [ ] 三端版本一致，命名和包结构符合预检规则。
- [ ] 对应模块归档、`config/module-archives.json` 和更新说明已准备。
- [ ] 测试用 GitLink / GitHub 目标、权限和 Release 标签已确认。
- [ ] 已备份两个源当前清单和附件摘要；确认测试不会破坏正式版本。
- [ ] `publisher-workspace` 可写，且没有另一个发布器实例执行远端操作。

## 3. 真实三端双源程序发布

### 3.1 创建与确认

- [ ] 在发布中心创建程序版本批次并收件。
- [ ] 三端产物均被发现，文件名、大小和 SHA-256 与外部记录一致。
- [ ] 单文件替换任一候选后，旧预检和确认立即失效；重新收件后恢复。
- [ ] 预检显示版本、平台、架构、结构、模块归档、更新说明和双源配置全部通过。
- [ ] 集中确认摘要准确展示两个源、三端产物、警告、跳过项和完整阶段顺序。

### 3.2 执行与远端证据

- [ ] GitLink 三端包上传完成并回读大小与 SHA-256。
- [ ] GitHub 三端包上传完成并回读大小与 SHA-256。
- [ ] 在任一源三端包未全部验证前，两个源的新清单均不可见。
- [ ] GitLink 清单只在双源附件全部就绪后切换。
- [ ] GitHub 清单只在双源附件全部就绪后切换。
- [ ] 两个源最终清单版本、平台键、URL、大小和 SHA-256 与批次一致。
- [ ] 批次最终状态为 `completed`，看板显示索引切换完成且远端回读通过。
- [ ] 客户端分别选择 GitLink 和 GitHub，都能发现同一测试版本并从对应源下载。

### 3.3 模块、内容与 Hub 抽样

- [ ] 模块归档在两个源上均可读取，大小和 SHA-256 与配置一致。
- [ ] 创建一个游戏内容批次，确认附件先验证、`catalog.json` 最后切换。
- [ ] 创建一个 Hub 批次，确认卡带 / 公告快照先验证、主表最后切换。
- [ ] 客户端从两个源读取的游戏目录、Hub 主表和公告结果一致。

## 4. 真实故障注入与恢复

每次故障使用独立测试批次，避免前一项的远端状态污染后一项。

### 4.1 安全暂停

- [ ] 在数据包上传阶段请求安全暂停。
- [ ] 当前原子请求结束后批次进入 `paused`，没有提前切换清单。
- [ ] 重启发布器后可看到该批次和恢复建议。
- [ ] 执行恢复时已远端回读验证的附件被复用，未知附件先探测后决定重试。
- [ ] 恢复完成后事件链包含暂停、恢复和最终完成，未重复切换已验证阶段。

### 4.2 进程中断

- [ ] 在附件上传期间强制结束发布器进程。
- [ ] 再次启动后原 `running` 批次转为 `interrupted`。
- [ ] 重新核对冻结输入和远端现状后，从下一个安全阶段继续。
- [ ] 产物被修改时恢复被拒绝，批次返回待预检状态。

### 4.3 双源部分失败

- [ ] 注入 GitLink 附件上传失败，确认两个源均未切换清单。
- [ ] 注入 GitHub 附件上传失败，确认两个源均未切换清单。
- [ ] 注入第一源清单已切换、第二源清单失败，批次进入 `degraded` 而非 `completed`。
- [ ] 使用标准恢复或关联批次的高级维护补齐失败源，最终双源一致。
- [ ] 不可恢复失败后重新发起单源维护时，必须重新输入精确确认文本。

## 5. 新旧 UI 功能对等验收

按 `docs/publisher-compatibility-map.md` 逐行核对：

- [ ] 程序更新双源发布有明确新入口，结果与兼容路径合同一致。
- [ ] 模块归档、游戏内容、Hub / 公告双源发布均有明确新入口。
- [ ] 暂停、继续、重启恢复和失败诊断可从批次看板完成。
- [ ] 三端候选可单文件替换，替换后确认失效。
- [ ] 验收快照可附加、查看，并在变化后使确认失效。
- [ ] 远端删除、采用附件和单源发布只出现在高级维护层级。
- [ ] 高级维护无关联批次时拒绝执行；授权、成功和失败事件与真实结果一致。
- [ ] 仓库、令牌、发布目标和本地内容准备仍有可发现入口。
- [ ] 普通发布导航没有破坏性快捷动作。
- [ ] 新旧路径均未丢失原有错误提示、暂停反馈和必要日志。
