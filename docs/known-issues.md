# 已知问题清单

> 用途：集中记录已确认、但尚未安排即时修复的缺陷和体验问题。
>
> 不记录运行时自动生成的异常报告；后者仍由客户端“问题记录中心”保存。这里的条目用于开发排期、复现和验收。

## 维护规则

- 新问题使用稳定编号 `KI-XXX`，不要复用已关闭条目的编号。
- 每条问题应写明现象、影响范围、复现条件、期望行为、当前状态和计划修复版本。
- 问题修复并通过验证后，将状态改为“已解决”，保留条目和验证结论；不要直接删除历史。
- 本文件记录产品和开发待办；当前任务过程写入 `docs/agent/HANDOFF.md`，长期技术原则写入 `docs/agent/DECISIONS.md`。

## 待处理

### KI-001：一键排错将充足的磁盘空间误显示为红色

- **状态**：待排期
- **优先级**：P2（体验问题，不阻断功能）
- **发现日期**：2026-08-23
- **影响范围**：客户端“一键排错”中的游戏目录磁盘空间检查；当前活动模块为 `0.2.0`。
- **现象**：游戏目录所在磁盘仍有约 110 GB 可用空间时，检查结果显示为红色，并出现“查看解决方案”按钮。
- **复现条件**：选择存在的游戏目录后运行“一键排错”。
- **当前原因**：`_quick_check_game_directory()` 无论剩余空间多少都会传入 `disk-space` 解决方案 ID；渲染逻辑只要存在该 ID 就使用危险色并显示解决方案入口。
- **期望行为**：仅当可用空间低于明确阈值时标红并展示磁盘空间解决方案；空间充足时应以普通颜色显示，并明确提示空间充足。
- **计划修复版本**：未定；与下一批“一键排错”体验优化统一处理。
- **验收要点**：覆盖低于阈值、等于阈值和高于阈值三种空间值，验证颜色、文字和解决方案入口均符合预期。

### KI-002：启动时反复输出报错指南缓存/详情格式警告

- **状态**：待排期
- **优先级**：P2（日志噪音，可能影响可选报错指南内容）
- **发现日期**：2026-08-23
- **影响范围**：客户端启动时的报错指南远端索引、本地缓存索引与可选详情加载；当前活动模块为 `0.2.0`。
- **现象**：从源码运行 `launcher.py` 时，控制台反复输出 `Ignoring invalid remote/cache guide index: unsupported guide schema`，以及多个 `guide_id must be a lowercase id` 警告；但随后仍输出 `Starting application module 0.2.0`。
- **复现条件**：当前工作区保留 `data/guides/` 中的缓存数据后启动客户端。
- **已知行为**：客户端将不符合当前 schema 或 ID 校验规则的远端/缓存指南主动忽略，并继续尝试使用其他可用来源，因此该日志本身不表示客户端启动失败。
- **待确认原因**：缓存索引 schema 与当前客户端要求不一致；可选详情文件的 `guide_id` 校验失败。需后续核对缓存生成、下载保存与路径/ID 转换链路，确认是历史缓存遗留、文件命名转换还是远端内容格式问题。
- **期望行为**：兼容可安全迁移的旧缓存，或在发现不可用缓存后一次性清理/刷新并避免重复告警；用户界面应仍能可靠展示内置或已验证的指南。
- **计划修复版本**：未定；与下一批报错指南缓存体验优化统一处理。
- **验收要点**：准备旧 schema、无效 ID 与合法缓存三类样本，验证启动不受阻、每类警告不重复刷屏、可用指南正常加载，且无效缓存可被安全刷新或忽略。

### KI-003：从一键排错进入解决方案后，右上角返回按钮未回到一键排错

- **状态**：待排期
- **优先级**：P2（导航体验问题，不阻断功能）
- **发现日期**：2026-08-23
- **影响范围**：客户端“一键排错”跳转至“报错指南/解决方案”详情后的返回导航；当前活动模块为 `0.2.0`。
- **现象**：在一键排错结果中点击“查看解决方案 →”后，右上角按钮固定显示“返回指南”；点击后回到解决方案列表，而不是此前的一键排错页面。
- **复现条件**：在“一键排错”中生成带有解决方案入口的检查结果，点击“查看解决方案 →”。
- **当前原因**：`_open_solution_article()` 直接切换到“常见问题教程”并展示详情，但未保存来源页面；解决方案详情页的返回按钮固定绑定 `_show_solution_list()`。
- **期望行为**：从一键排错进入的解决方案详情，右上角按钮应显示“回到一键排错”，并返回保留当前检测结果的一键排错页面；从报错指南列表正常进入的详情，仍保持“返回解决方案”。
- **计划修复版本**：未定；与下一批一键排错体验优化统一处理。
- **验收要点**：分别验证一键排错入口和报错指南列表入口：按钮文案、返回目标、检测结果保留情况均正确；重复进入/返回后不残留错误的导航来源。

- **待设计事项**：定义工具目录索引/安装状态、版本或更新策略、命令行参数与工作目录声明、可执行类型白名单、输出长度与编码处理、超时/取消策略、运行日志保留和跨平台 UI 行为；还需明确“卸载”是否包含清理运行日志。
- **计划修复版本**：未定；需单独制定数据模型、UI 和安全验收方案后实施。
- **验收要点**：分别覆盖 Windows、SteamOS、macOS 的平台过滤；下载、重复下载、受控卸载、确认运行、成功/失败/超时运行、输出捕获与图形程序无法捕获输出的提示；同时验证从报错指南引用工具与从常用工具入口访问的是同一工具和同一受控安装状态。

### KI-005：SteamOS 测试虚拟机因 VirtualBox I/O 缓存错误暂停

- **状态**：待排期
- **优先级**：P1（阻断 SteamOS 原生构建与验收环境）
- **发现日期**：2026-08-23
- **影响范围**：SteamOS x86_64 虚拟机及其宿主机 VirtualBox 存储；影响 SteamOS 客户端构建、更新流程和真实游戏验收。
- **现象**：虚拟机运行时被暂停，VirtualBox 提示介质 `ahci-0-1` 的 I/O cache 更新失败，错误 ID 为 `BLKCACHE_IOERR`，返回码为 `VERR_INVALID_PARAMETER`，严重性标记为“非致命性错误”。
- **复现条件**：当前 SteamOS 虚拟机运行期间，VirtualBox 写入挂载在 AHCI 控制器端口 1 的虚拟介质时发生错误。
- **待确认原因**：VirtualBox 已提示需检查宿主机磁盘可用空间与磁盘健康；当前尚未确认是宿主磁盘空间、底层磁盘/文件系统异常、虚拟磁盘文件状态、VirtualBox 缓存设置或其他宿主环境问题。
- **期望行为**：定位并修复宿主机或虚拟磁盘问题后，恢复虚拟机运行；在重启后完成一次 SteamOS 基础环境检查，确认项目文件、构建依赖和虚拟磁盘读写均正常。
- **计划修复版本**：不适用（开发/验收环境维护问题）。
- **验收要点**：先保存或确认暂停前状态；核验宿主机对应磁盘可用空间、文件系统与虚拟磁盘文件可读写；恢复或重启虚拟机后观察无重复 `BLKCACHE_IOERR`，并完成 SteamOS 端基础命令、项目目录访问和一次目标构建/验证。

### KI-006：一键排错支持开发者声明式调入随程序下载的诊断工具

- **状态**：需求待设计
- **优先级**：P1（扩展一键排错能力并降低重复实现）
- **发现日期**：2026-08-23
- **影响范围**：客户端“一键排错”、报错指南工具模型、模块/程序随附资源与发布流程；当前活动模块为 `0.2.0`。
- **需求概述**：允许开发者开发一个诊断工具，并通过受版本控制的声明/标注将其注册为一键排错检查项。客户端在对应程序或模块资源下载时取得该工具，并由一键排错调入，以复用工具实现，避免将相同诊断逻辑重复写入 UI 检查代码。
- **配置边界**：工具的注册、启用、平台范围、版本、下载来源、参数、工作目录和结果解析均由开发者在项目/发布资源中维护；最终用户不提供工具增删、任意命令编辑或任意文件执行入口。
- **运行边界**：一键排错调入的工具必须是已审核、适用于当前平台且以诊断为目的的受控工具。需与既有“非破坏性检查”原则保持一致：默认不得修改游戏文件、系统设置或网络配置；若未来存在会产生修改的工具，必须从一键排错流程中分离并另行进行明确用户确认。
- **下载与生命周期**：工具应与当前程序/模块版本关联，采用受控目录、平台过滤、HTTPS、非空校验和临时文件原子替换；需设计缓存命中、版本更新、缺失/下载失败回退与卸载策略，不能把工具当作用户自行管理的任意附件。
- **结果整合**：工具运行不应阻塞主界面；其结构化结果、标准输出/错误、退出码、超时和失败原因应转换为一键排错的检查行、问题记录或对应解决方案入口，而不是要求每个工具重复实现一套 UI。
- **现有基础**：当前 `GuideTool` 已支持开发者声明工具 ID、平台、下载资源和运行模式，且一键排错已有固定步骤队列；二者尚未建立声明式关联，工具下载完成后目前也只打开目录。
- **待设计事项**：定义一键排错工具 schema、稳定结果码与结果解析协议、允许的运行模式与参数白名单、超时/取消/并发模型、下载时机与版本耦合、离线回退、输出脱敏/长度限制、测试夹具及发布器对工具资源的校验。
- **计划修复版本**：未定；需先完成数据模型与安全边界设计，再分阶段接入首个只读诊断工具。
- **验收要点**：开发者仅通过声明接入一个 Windows/SteamOS/macOS 适用的只读工具；用户无需手动下载、打开或编辑命令即可在一键排错中运行；工具结果能正确显示、超时/失败不阻断其余检查、平台不适用时不显示，并证明没有重复实现该工具的核心诊断逻辑。

### KI-007：一键排错列举本机安全软件并提供受控打开入口

- **状态**：需求待设计
- **优先级**：P1（安全软件干扰诊断能力）
- **发现日期**：2026-08-23
- **影响范围**：Windows 客户端“一键排错”、疑似安全软件拦截的解决方案与系统安全入口；当前活动模块为 `0.2.0`。
- **需求概述**：新增开发者维护的安全软件检测工具，尽可能列举本机已注册或可识别的安全产品，包括 Windows Defender/Windows 安全中心、火绒、360 及用户指定的其他产品（“艾可菲”的具体产品映射待确认）。一键排错应显示检测到的列表。
- **展示与操作**：每个检测到的条目显示产品名称、检测来源/状态及适用操作；可提供“打开”按钮，在客户端内通过固定、受控的启动方式打开对应安全软件或 Windows 系统安全界面，避免用户手动寻找入口。找不到可靠启动方式时必须禁用按钮并说明原因，不能猜测任意可执行路径或命令。
- **检测边界**：检测结果是尽力而为的本机诊断结果，不能承诺识别所有安全产品，也不能仅凭检测结果断言某个产品拦截了本程序。产品匹配、显示名、启动 URI/路径和平台范围必须由开发者允许列表维护；不得使用用户可编辑的命令、注册表路径或任意文件路径。
- **安全与隐私边界**：仅列举与打开入口，不关闭防护、不添加排除项、不恢复隔离文件、不修改安全软件设置；已检测到的产品清单默认只在本机界面展示，除非用户明确导出诊断信息。Windows 专属功能在 SteamOS/macOS 隐藏。
- **现有基础**：项目已有“疑似安全软件拦截”启发式分类与打开固定 Windows 安全页面的限制，但一键排错尚未列举已安装安全软件，也没有面向第三方产品的受控启动清单。
- **待设计事项**：确定可接受的检测来源与失败回退、产品允许列表和启动策略、重复/残留产品去重、权限与管理员提示、不可打开状态、结果展示与导出脱敏规则，以及针对 Windows Defender、火绒、360 和其他支持产品的测试夹具。
- **计划修复版本**：未定；在明确 Windows 检测与启动允许列表后分阶段接入。
- **验收要点**：在仅启用 Windows 安全中心、安装一个受支持第三方产品、安装多个产品、无可识别产品、检测接口不可用和产品已卸载残留等场景中验证列表准确且不夸大；确认打开按钮只调用允许列表中的固定入口，无法打开时有明确提示，并证明不执行任何防护配置修改。

### KI-008：新增补丁工具，集中查看与操作当前游戏补丁

- **状态**：需求待设计
- **优先级**：P1（补丁诊断与维护能力）
- **发现日期**：2026-08-23
- **影响范围**：客户端常用工具/报错指南入口、当前选中游戏的补丁安装与下载工作流；当前活动模块为 `0.2.0`。
- **需求概述**：新增“补丁工具”入口，面向当前选中且支持补丁的游戏，集中展示补丁位置、安装/审计状态和云端可用补丁信息，并提供受控的补丁相关操作。
- **状态与位置展示**：详情页应明确显示游戏目录、补丁相关文件/目录的实际位置、补丁安装记录与完整性审计结果、原始库备份状态、当前平台适用性及可用云端补丁资源状态。不存在补丁配置、未选择游戏或游戏目录无效时，应解释原因并禁用不适用操作。
- **打开操作**：提供“打开补丁目录”和“打开补丁文件”等按钮，只能打开当前卡带补丁配置和已审计安装记录解析出的受控路径；路径不存在或文件不适用时禁用按钮并说明，禁止让用户输入或执行任意本地路径。
- **重新下载操作**：提供“从云端重新下载补丁”操作，复用现有补丁资源下载、完整性校验、任务队列和补丁引擎流程，不重复实现下载或应用逻辑。需要明确区分“重新下载到受控缓存”和“下载后应用到游戏目录”；后者必须展示影响、确认游戏未运行并取得用户明确确认。
