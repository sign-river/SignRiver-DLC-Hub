# 发布器新旧入口能力映射与回退说明

> 状态：阶段 6 删除旧入口前的控制文档
> 更新日期：2026-08-17
> 适用版本：发布器流程化与模块化重构工作区

## 1. 使用原则

- 标准发布优先走“发布中心”的持久化批次；旧“构建与发布（兼容）”仅用于尚未完成真实验收时的回退。
- 新旧路径不得同时对同一版本、同一游戏或同一 Hub 范围执行远端副作用。
- 回退到旧路径前必须停止新批次执行，读取批次诊断和远端现状；不得仅凭按钮状态判断上传是否完成。
- 任何单源发布、远端删除或采用远端附件都属于高级维护，必须关联批次并完成精确文本确认。
- 文档和审计中不得保存令牌、Cookie、账号密码或私有下载凭据。

## 2. 能力映射

| 旧入口 / 能力 | 新位置 | 新路径证据 | 当前处置 |
| --- | --- | --- | --- |
| 程序更新双源镜像发布 | 发布中心 → 程序版本批次 | 三端产物冻结、双源附件回读、清单最后切换、最终回读 | 新路径主入口；真实演练前保留旧入口 |
| 程序更新单源发布 | 高级维护，并关联发布中心批次 | `maintenance_authorized` 后由真实回调写 completed / failed | 仅修复或受控回退，不作为标准流程 |
| 模块归档双源发布 | 程序版本批次的模块归档产物与预检 | 模块文件、大小和 SHA-256 纳入批次输入与双源阶段 | 新路径主入口；真实演练时核对模块附件 |
| 模块归档单源发布 | 高级维护，并关联发布中心批次 | 一次性维护授权和真实结果审计 | 仅补齐失败源 |
| 当前游戏内容双源发布 | 内容与卡带 → 创建游戏内容批次 → 发布中心执行 | 内容附件先上传和回读，`catalog.json` 最后切换 | 新路径主入口 |
| 当前游戏内容单源发布 | 高级维护，并关联发布中心批次 | 维护授权、单写者租约、真实结果审计 | 仅修复或回退 |
| Hub / 公告双源发布 | 内容与卡带 → 创建 Hub 批次 → 发布中心执行 | 完整快照附件先回读，主表最后切换 | 新路径主入口 |
| Hub 单源发布 | 高级维护，并关联发布中心批次 | 维护授权和真实结果审计 | 仅修复或回退 |
| 发布暂停 / 继续 | 发布中心 → 安全暂停 / 执行·恢复 | 批次阶段检查点、暂停状态和恢复事件 | 新路径主入口；旧上传暂停用于兼容流程 |
| 发布前校验与确认 | 发布中心 → 运行预检 / 确认冻结输入 | 硬门禁、警告、产物指纹和阶段顺序集中展示 | 新路径主入口 |
| 单文件替换三端候选 | 发布中心 → 替换 Windows / SteamOS / macOS 包 | 替换后旧预检与确认失效并重新冻结 | 新路径主入口 |
| 人工发布验收 | 验收中心 → 记录结果 → 附加到当前批次 | 验收快照进入批次，变化后确认失效 | 新路径主入口 |
| 批次故障诊断 | 发布中心选择批次 → 诊断 | 状态、阶段、事件和恢复建议 | 新增能力 |
| 审计导出 | 发布中心选择批次 → 导出审计 | 递归脱敏的批次与事件快照 | 新增能力 |
| 远端单个 / 全部删除 | 高级维护 | 关联批次、影响摘要、精确确认和真实结果事件 | 永久保留为高风险维护，不迁入标准流程 |
| 采用远端附件 | 高级维护 | 关联批次、精确确认和真实结果事件 | 永久保留为高风险维护 |
| 仓库、令牌和发布目标配置 | 资源管理 / 兼容配置区域 | 新批次读取同一配置形成 `remote_targets` | 暂不删除；待配置界面独立化后再迁移 |
| 本地 DLC、补丁、卡带和公告准备 | 内容与卡带、卡带管理 | 创建内容或 Hub 批次前校验必需输入存在 | 保留业务能力，不与远端编排混合 |

## 3. 允许回退的条件

只有满足以下任一条件时才使用兼容入口：

1. 新路径在真实验收中出现阻断，且批次诊断表明尚未切换任一远端索引；
2. 新路径缺少明确替代能力，能力映射表仍标记为“暂不删除”；
3. 已形成 `degraded`，标准补齐动作不可用，需要高级维护对失败源做单源修复；
4. 操作者需要读取或修复历史兼容发布状态，而非启动新的标准发布。

回退前必须记录：批次 ID、当前状态、最后成功阶段、两个源的附件与索引现状、选择回退的原因。记录只保存摘要，不保存凭据。

## 4. 禁止回退的情况

- 新批次仍为 `running` 或仍持有单写者租约；
- 无法判断远端请求是否成功，且尚未做远端回读；
- 试图绕过版本、平台、架构、包结构、哈希或双源配置硬门禁；
- 只为跳过集中确认或人工验收记录；
- 对同一目标同时启动新旧路径；
- 当前清单已经引用新包，却准备删除或覆盖这些包。

## 5. 兼容入口删除门槛

某项旧入口只有同时满足以下条件才可删除：

- 本表存在明确的新位置和操作步骤；
- 自动化覆盖准备、执行、暂停、恢复、失败和审计合同；
- 真实 GitLink + GitHub 演练已验证对应能力；
- 新旧 UI 人工对等验收已通过；
- 若涉及恢复，至少一次真实故障注入和重启恢复已通过；
- 操作指南已更新，且保留可执行的故障回退方案。

删除应按能力逐项进行，每次删除只覆盖一组已验收入口，并运行对应发布器专项回归；不得一次性移除全部兼容状态。
