# 桌面界面关闭与组件销毁标准

> 适用范围：SignRiver DLC Hub 客户端、发布器及之后新增的 CustomTkinter / Tk 窗口。

## 目标

关闭程序时，用户不得看见主窗口框架仍在、其中的按钮、卡片、输入框或弹窗逐个消失的过程。组件的资源生命周期也必须遵循**内部（叶子）组件先销毁，外部容器和根窗口最后销毁**的顺序。

## 统一执行顺序

所有根窗口的关闭入口（包括 `WM_DELETE_WINDOW` 和应用主动退出）必须按下列顺序执行：

1. **拒绝新的工作**：设置关闭标记，停止 UI 事件泵、定时回调和新任务入口；仍在运行且可能影响用户数据的任务要先确认或取消。
2. **先隐藏可见外壳**：在释放任何可见子组件前调用根窗口的 `withdraw()`。这一步只隐藏，不销毁根窗口，避免用户看到递归销毁动画。
3. **释放受控的临时窗口**：关闭并清空所有保存了引用的 `Toplevel`、弹窗、模态窗口和 grab；其关闭函数应当能在关闭途中重复调用而不报错。
4. **从叶到根销毁主树**：递归处理每个 `winfo_children()` 子树，先销毁其全部后代，再销毁该子组件。不得在根窗口可见时直接依赖 `root.destroy()` 的隐式递归。
5. **最后销毁根窗口**：子树已清理后才调用 `quit()` 结束事件循环，随后调用根窗口 `destroy()`。根窗口是整个 UI 树唯一允许最后销毁的外层组件。

## 实现约束

- 关闭路径必须可重入：第二次关闭请求应直接返回，不能重复释放资源。
- 子组件可能被延迟回调或其父组件提前销毁；销毁时应容忍 `TclError`，并以“最终组件不存在”为目标。
- 后台线程和 `after()` 回调在提交 UI 更新前必须尊重关闭标记，不能在组件销毁后重绘界面。
- 新增 `CTkToplevel`、模态窗口或定时器时，必须在关闭路径中登记并覆盖其释放方式。
- 不要为了保证顺序而盲目整树复制代码；客户端修改须同时按活动版本的定向同步规则处理。

## 回归验证

每次修改关闭流程时，至少应有自动化断言覆盖以下顺序：

- `withdraw()` 早于任一子组件销毁；
- 已登记的临时窗口早于根窗口关闭；
- 递归子树销毁早于 `quit()` 和根窗口 `destroy()`；
- 根窗口 `destroy()` 是关闭路径中最后一个销毁动作。

若可以启动图形界面，还应手动打开至少一个弹窗或动态列表后关闭程序，确认屏幕上没有“外壳保留、内部逐项消失”的可见过程。
