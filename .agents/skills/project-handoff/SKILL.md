# SignRiver DLC Hub：转出当前上下文

用户完成任务、准备切换对话或要求整理交接时，执行以下流程。此技能用于**转出**上下文；进入新对话的核对使用 `project-context-switch`。

不要求用户输入特定斜杠命令。以下自然语言都应触发本技能：

- “帮我整理交接，准备开新对话”
- “这项任务先到这里，记录下一步”
- “更新 HANDOFF，交给下一位 AI”
- “结束当前开发工作并写好交接”

`/project-handoff` 只是可选的简写。

## 收集真实状态

在写交接前，先检查：

1. `git branch --show-current`、`git rev-parse HEAD`、`git log -1 --oneline`；
2. `git status --short`、必要时 `git diff --stat` 和 `git diff --check`；
3. 本任务实际执行过的测试、构建、静态检查及其结果；不要把未执行项写成通过；
4. 与发布、资产、版本号或外部环境有关的未完成前置条件。

交接与真实状态不一致时，以代码、Git 和可重复验证结果为准。

## 更新交接文档

以最小必要改动更新 `docs/agent/HANDOFF.md`，包括：

- 当前目标与已完成结论；
- 实际修改范围（关键文件或模块）；
- 验证命令与结果，以及明确标注的未执行测试；
- 已知风险、外部依赖和不可宣称为已完成的事项；
- 可直接执行的下一步。

不得记录密码、令牌、Cookie、账号、私有下载凭据或大段原始日志。

## 长期决策

只有在本任务形成了可复用的技术方案、稳定约束或失败经验时，才同步更新 `docs/agent/DECISIONS.md`。临时进度、一次性报错和短期待办仅保留在 `HANDOFF.md`。

## Git 与发布保护

- 不得为了整理交接而重置、清理或覆盖任何未提交改动。
- 更新交接文档不等于自动提交；除非用户明确要求，否则不要执行 `git commit`。
- 即使已提交，也不得自动 `git push`；只有用户明确要求“推送”或“提交并推送”时才能推送。
- 涉及发布时，保留 `AGENTS.md` 中“先上传并核验资产、再由用户决定 push”的顺序。

## 结束报告

向用户简要说明：已更新的文档、当前分支与 HEAD、未提交改动、验证结果、风险和下一步。若没有更新文档的必要，也要明确说明原因。
