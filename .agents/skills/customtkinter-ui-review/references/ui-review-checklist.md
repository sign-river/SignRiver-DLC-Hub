# CustomTkinter 界面审查清单

## 导航与页面来源

| 现象 | 优先修复方式 |
| --- | --- |
| 标题栏与正文出现两个“返回” | 保留一个直接返回上一级的入口；删除或改造重复入口。 |
| 详情页总回到总览 | 保存进入来源，或在打开详情时传入返回回调。 |
| 结果按钮进入的页面与说明不一致 | 让按钮跳到实际功能详情；解决方案与工具详情分别命名。 |
| “返回”点击没有反应 | 检查回调是否绑定、页面是否已加入/隐藏于同一容器、来源状态是否被重置。 |

## 一键排错与异步项目

| 现象 | 优先修复方式 |
| --- | --- |
| “正在检查”和“检查完成”显示两行 | 在开始时记录结果索引/对象，在回调内替换内容。 |
| 用户停止后旧结果又出现 | 在 UI 回调中确认任务仍处于运行状态。 |
| 一项失败后没有操作入口 | 同一结果行中提供解决方案或工具详情；不要新建重复行。 |
| 复制结果仍有旧状态 | 更新结果模型时同步更新复制用文本。 |

## 布局与可读性

| 风险 | 处理建议 |
| --- | --- |
| 右侧多个按钮压扁左侧文字 | 使用可扩展标签区与固定宽度按钮；必要时分行或收纳低频操作。 |
| 长路径、报错或说明溢出 | 允许换行，设置合理 `wraplength`；保留复制/打开目录等可行动作。 |
| 纵向空间足够但组件被挤压 | 检查父容器的 `pack/grid` 权重、`expand/fill` 与固定高度；不要只缩小字号。 |
| 操作栏和返回按钮混在一起 | 导航独立成行，页面操作按频率分组。 |
| 空列表只留下空白 | 显示解释性空状态和下一步，例如“重新扫描”“打开工具详情”。 |

## 结果页的最低反馈

- **进行中**：用户看到当前正在做什么；按钮按需禁用或允许取消。
- **成功**：一句结论，必要时显示下一步或详情。
- **无数据**：说明“未发现”不等于“系统一定没有该能力/问题”。
- **失败**：简要异常类型/可见原因 + 对应解决方案或日志入口。
- **取消**：明确表示已停止，异步结果不得覆盖取消状态。
